A glossary is useful when the same words show up in the code, the docs, and the release notes with slightly different jobs.
It keeps the vocabulary steady while the rest of the project keeps moving.

===

<dl>
<dt>Preview</dt><dd>A local rendering pass that lets you inspect pages before publishing</dd>
<dt>Frontmatter</dt><dd>The YAML block at the top of a Markdown file</dd>
<dt>Slug</dt><dd>The route fragment derived from a folder or page name</dd>
<dt>Theme</dt><dd>The presentation layer that turns content into HTML</dd>
</dl>

<abbr title="hypertext markup language">HTML</abbr> and <abbr title="cascading style sheets">CSS</abbr> appear here only so the abbreviations stay familiar.
